# Проект 1. «5 букв»

Консольная игра в духе Wordle. Программа загадывает слово из 5 русских букв,
у игрока 6 попыток. После каждой попытки — подсказка по буквам:

```text
Загадано: озеро
Ввод:     арбуз
Результат: ❌🟡❌❌🟡

✅ буква на месте   🟡 есть, но не там   ❌ буквы нет
```

## Запуск игры

Запустить игру:

```bash
./gradlew run
```

Запустить тесты:

```bash
./gradlew check
```

### Детерминированный режим

Для воспроизводимого запуска игры можно указать seed:

```bash
./gradlew run --args="--seed 123"
```

Одинаковый seed при неизменном словаре позволяет получить одинаковое загаданное слово.

### Правила игры

- необходимо угадать русское слово из 5 букв;
- на игру даётся 6 попыток;
- `✅` — буква стоит на правильной позиции;
- `🟡` — буква есть в загаданном слове, но находится на другой позиции;
- `❌` — буквы нет в загаданном слове;
- некорректная попытка не расходует попытку игры;
- игра завершается победой при угадывании слова или поражением после последней допустимой попытки.

### Повторное воспроизведение игры

Игру можно воспроизвести с использованием seed и списка попыток:

```bash
./gradlew run --args="--seed 123 --replay арбуз,озеро,сорок"
```

При одинаковом seed и одинаковом списке попыток результат воспроизведения будет одинаковым.

## Загрузка словаря

Загрузка словаря происходит через метод `loadWords()` класса `Dictionary`.

Источник слов находится в:

```text
src/main/resources/dictionary.txt
```

При загрузке каждая строка обрабатывается отдельно:

- пустые строки пропускаются;
- строки, начинающиеся с `#`, считаются комментариями;
- в словарь добавляются только слова длиной 5 символов;
- файл читается в кодировке UTF-8.

После загрузки список слов становится неизменяемым. Это позволяет использовать один
и тот же словарь в разных игровых сессиях и не изменять его случайно из других частей
программы.

Словарь является частью ресурсов приложения и загружается через `getResourceAsStream()`,
поэтому код не зависит от абсолютного пути к файлу на компьютере.

## Игровая сессия

Состояние одной игры хранится в классе `GameSession`.

Сессия содержит:

- `answer` — загаданное слово;
- `maxAttempts` — максимальное количество попыток;
- `attemptsUsed` — количество использованных попыток;
- `attemptsHistory` — история попыток;
- `status` — текущее состояние игры.

Начальное состояние новой игры:

```text
attemptsUsed = 0
attemptsHistory = []
status = IN_PROGRESS
```

Для состояния игры используется перечисление `GameStatus`:

```text
IN_PROGRESS
WIN
LOSE
```

При создании `GameSession` проверяется корректность основных данных:

- загаданное слово должно состоять ровно из 5 букв;
- `maxAttempts` должен быть больше 0.

История попыток хранится внутри сессии и не предоставляется наружу как изменяемый
список. Это не позволяет внешнему коду напрямую изменить состояние игры.

## Создание игры

Создание новой игровой сессии выполняется через `GameService.startGame()`:

```text
startGame(dictionary, maxAttempts, seed)
        ↓
    выбор слова
        ↓
   GameSession
```

Метод получает словарь, максимальное количество попыток и `seed`.

Слово выбирается из переданного словаря, после чего выбранное слово и лимит попыток
используются для создания новой `GameSession`.

Пустой словарь не позволяет создать игру и приводит к `IllegalArgumentException`.

## Воспроизводимый выбор слова

Для выбора слова используется `seed` — начальное значение генератора случайных чисел.

Это позволяет воспроизводить результат случайного выбора:

```text
одинаковый dictionary + одинаковый seed
                  ↓
          одинаковый answer
```

Например, две игры, созданные с одним и тем же словарём и `seed = 42`, получают
одинаковое загаданное слово.

Это используется в тестах, потому что тест не должен зависеть от случайного результата
конкретного запуска.

При этом параметр `maxAttempts` отвечает только за количество попыток и не должен
влиять на выбор загаданного слова.

## Инварианты MR1

Игровая модель поддерживает следующие ограничения:

- загаданное слово состоит из 5 букв;
- игра создаётся только с положительным количеством попыток;
- загаданное слово выбирается из переданного словаря;
- новая игра начинается в состоянии `IN_PROGRESS`;
- количество использованных попыток при создании равно `0`;
- история попыток при создании пуста;
- завершённая игра не должна принимать новые попытки.

Эти ограничения позволяют MR2 использовать `GameSession` как корректное состояние
игры, не проверяя заново базовые инварианты в каждом месте.

## Тестирование MR1

Для MR1 написаны обязательные тесты, проверяющие поведение игровой модели.

### Словарь

Проверяется:

- словарь содержит минимум 50 слов;
- каждое слово имеет длину 5;
- пустой словарь отклоняется.

### Seed

Проверяется, что одинаковые словарь и `seed` приводят к одинаковому загаданному
слову.

Для теста используется фиксированный `seed`, поэтому результат воспроизводим
между запусками.

### Игровая сессия

Проверяется начальное состояние созданной сессии:

```text
answer       → выбранное слово
maxAttempts  → переданный лимит
attemptsUsed → 0
history      → пустая
status       → IN_PROGRESS
```

Тесты работают с объектами игровой модели напрямую и не используют консольный ввод
или вывод.

## Обработка попытки

Проверка пользовательской попытки выполняется через `GameService.applyGuess()`.

Перед обработкой попытки выполняются проверки:

- игра должна находиться в состоянии `IN_PROGRESS`;
- введённое значение не должно быть `null`;
- слово должно состоять ровно из 5 букв;
- слово должно присутствовать в словаре.

Невалидная попытка отклоняется через `IllegalArgumentException` и не увеличивает
количество использованных попыток.

После успешной проверки слово добавляется в историю попыток, а состояние игры
обновляется при необходимости.

## Проверка букв

Для каждой попытки формируется строка из пяти символов:

```text
✅ — буква находится на правильной позиции
🟡 — буква есть в загаданном слове, но находится на другой позиции
❌ — подходящего вхождения буквы нет
```

Проверка выполняется в два этапа:

1. сначала определяются точные совпадения `✅`;
2. затем оставшиеся буквы проверяются на наличие свободных вхождений в загаданном
   слове и получают `🟡`.

При этом каждое вхождение буквы в загаданном слове может быть использовано только
один раз. Это позволяет корректно обрабатывать повторяющиеся буквы.

## Завершение игры

После успешной попытки:

- если слово полностью угадано, игра переходит в `WIN`;
- если использована последняя доступная попытка и слово не угадано, игра переходит
  в `LOSE`;
- до достижения одного из этих состояний игра остаётся `IN_PROGRESS`.

После завершения игры новые попытки отклоняются.

При поражении `GuessResult` содержит загаданное слово, чтобы интерфейс мог показать
его игроку.

## Результат попытки

`GameService.applyGuess()` возвращает `GuessResult`.

Он содержит:

- введённое слово;
- результат проверки букв;
- текущее состояние игры;
- загаданное слово при поражении.

Игровая логика не выполняет консольный ввод или вывод. Это позволяет тестировать
`GameService` независимо от интерфейса программы.

## Тестирование MR2

Для MR2 проверяются:

- отклонение `null`;
- отклонение слова неправильной длины;
- отклонение некорректных символов;
- отклонение слова, отсутствующего в словаре;
- отсутствие расхода попытки при невалидном вводе;
- корректное определение `✅`, `🟡` и `❌`;
- обработка повторяющихся букв;
- победа при угадывании слова;
- поражение после последней попытки;
- запрет попыток после завершения игры;
- корректное сохранение истории попыток.
